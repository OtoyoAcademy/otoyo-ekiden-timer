# Otoyo Ekiden Timer v0.14.4

v0.14.4 は、年度別大会管理の小修正版です。**Supabaseの追加SQLは不要**です。

## v0.14.4 の変更

- 管理者の「過去大会」一覧から、試行用・不要な過去大会を完全削除できるようにしました。
- 削除時は確認ダイアログを表示し、現在運用中の大会には影響しません。
- 過去大会専用の証書テンプレート／印画像がある場合は、Storage上の不要画像も整理します。
- 区間距離の入力欄を広げ、小数（例：`0.5`、`2.35`、`12.35`）が見切れにくいレイアウトへ修正しました。

# otoyo-ekiden-timer v0.14

## v0.14 の主な変更

- 管理者画面に「年度別大会管理」を追加
- 現在運用する大会は1つだけとし、新しい大会作成時に現在大会を自動アーカイブ
- 過去大会は閲覧専用で保存し、チーム正式順位・個人賞・個人記録を確認可能
- 過去大会の結果データをCSV出力可能
- 新大会作成時にコピー元を「現在大会 / 過去大会 / コピーなし」から選択可能
- コピー対象：会場、区間数、区間距離、表彰設定、証書テンプレート、ハンコ設定、事務局設定
- コピーしない対象：開催日、申込締切、申込受付状態、申込者、チーム、計測記録、結果
- 新大会作成時は申込受付をOFFで開始し、日付を設定後に管理者が受付開始できる安全仕様
- 年度切替時に旧チームアクセスコード・端末ロック・旧計測係/チームセッションを無効化
- 旧大会の計測端末が開いたままでも、新大会へ誤記録しにくいよう大会切替を検知してログアウト
- 証書テンプレート/印画像の保存先を大会ID別フォルダへ変更。将来のテンプレート差替えで過去大会用画像を上書きしない
- 現在大会の初期化時も過去大会アーカイブと管理者・計測係コードは保持

## v0.14 更新時の重要手順

1. Supabase SQL Editorで `supabase-patch-v0.14.sql` を1回実行
2. `Success. No rows returned` を確認
3. GitHub Pagesへv0.14のファイルを上書き
4. 管理者画面の「年度別大会管理」を確認

`supabase-patch-v0.14.sql` は、年度切替時に旧大会の計測係・チームセッション、端末ロック、チームコードを安全に無効化するRPCを追加します。既存の `ofes_*` テーブル等には触れません。

> **注意**：実データで最初の年度切替を行う前に、ダミーデータで「現在大会 → 新大会」を1回試し、過去大会一覧へ保存されることと、新大会の申込・チーム・計測が空になることを確認してください。

# otoyo-ekiden-timer v0.13

## v0.13 の主な変更

- 管理者画面に「表彰状・記録証テンプレート」を追加
- チーム表彰状・個人賞表彰状・個人記録証の標準PNGテンプレートを3種類内蔵
- 標準テンプレートをダウンロードし、Canva・PowerPoint等で編集後に再アップロード可能
- 大会名は既存の「大会・申込設定」から自動反映（名称変更に対応）
- 主催名・発行者名を管理者画面から変更可能
- ハンコは「印画像アップロード」「文字印自動生成」「なし」の3方式に対応
- 印画像が未設定でも文字印で出力可能
- 各テンプレートのサンプルプレビューをA4縦で確認可能
- 正式結果から表彰状を一括PDF・印刷可能
- 全区間の正式記録から個人記録証を一括PDF・印刷可能
- 完成PDFはSupabaseへ保存せず、必要なときだけブラウザで生成するため容量を抑制
- アップロード画像はPNG/JPG/WebP、1ファイル3MBまで
- Supabase Storageの非公開専用bucket `ekiden-assets` を使用し、印画像を一般公開しない。既存の `ofes_*` 等には触れない

## v0.13 更新時の重要手順

1. Supabase SQL Editorで `supabase-patch-v0.13.sql` を実行
2. `Success. No rows returned` を確認
3. GitHub Pagesへv0.13のファイルを上書き
4. 管理者画面の「表彰状・記録証テンプレート」で標準テンプレートのプレビューを確認
5. 必要なら標準PNGを編集してアップロード

※ SQLパッチを実行しなくても標準テンプレートの表示・印刷はできますが、編集版テンプレートや印画像をSupabaseへアップロードするにはパッチが必要です。

# otoyo-ekiden-timer v0.8 — GitHub Pages + Supabase

Firebase版 v0.7 を **GitHub Pages + Supabase** 構成へ移行した版です。
画面・計測ロジック・申込・掲示板・参加者閲覧など、v0.7までの機能を引き継ぎます。

## v0.8 の主な変更

- Firebase SDK / Realtime Database を削除
- Supabase JavaScript v2 をブラウザから利用
- Postgres + Realtime で複数端末同期
- Supabase Auth の Anonymous Sign-In を利用
- 管理者・計測係A/B/C・チームのアクセスコード判定をPostgres RPC側へ移動
- チーム用アクセスコードを公開チームデータから分離
- 申込の氏名・電話・メール・住所などを、管理者以外から読めないRLS構成に変更
- 端末重複防止ロックをSupabase側で管理
- Supabaseサーバー時刻から端末時刻の補正値を取得
- 通信断時のローカルキューと復旧後再送を継続

## 最初にやること

1. Supabaseプロジェクトを作成
2. Authentication で Anonymous Sign-Ins を有効化
3. SQL Editor で `supabase-setup.sql` を実行
4. Dashboard の Connect から Project URL と Publishable key を確認
5. `supabase-config.js` に入力
6. このフォルダの中身を `OtoyoAcademy/otoyo-ekiden-timer` へアップロード
7. GitHub Pages を `main / (root)` で公開

詳しくは `SUPABASE_MIGRATION.md` を参照してください。

## Supabase設定ファイル

```js
window.EKIDEN_SUPABASE_CONFIG = {
  url: "https://xxxxx.supabase.co",
  publishableKey: "sb_publishable_xxxxx"
};
```

ブラウザには **Publishable key** のみを置きます。Secret key / service_role key は入れません。
